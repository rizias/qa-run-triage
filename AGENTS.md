# AGENTS.md

qa-run-triage — CLI-инструмент разбора прогонов автотестов с сервера CI. На сервере CI только
читает; во внешнем мире меняет один каталог — `~/.qa-run-triage` (настройки, кэш, журнал,
отчёт). Журнал и отчёт не удаляются никогда.

## Команды

- Поставить зависимости: `npm ci`
- Включить git-хуки: `npx lefthook install`
- Полная проверка (сборка, типы, линтер, мёртвый код, тесты): `npm run check`
- Только тесты: `npm test`
- Проверка спецификации: `openspec validate --all`
- Восстановить команды работы со спецификацией: `openspec update`

## Спецификация — источник правды

Требования лежат в `openspec/specs/`, по разделу на область. Код обязан им соответствовать;
отступление без явного «да» владельца — дефект. Изменение поведения начинается с предложения
в `openspec/changes/`, а не с кода. Спецификация правится раньше кода.

## Правила кода

- Комментариев в коде нет — ни однострочных, ни блочных, ни JSDoc. Непонятный код
  переписывается, а не комментируется.
- Файл больше 300 строк делится по ответственности; предел держит правило ESLint
  `max-lines`, для тестов порог 500: размер теста задаёт число сценариев одного модуля.
  Сложность функции — правило `complexity`, порог 15. Файл `eslint-suppressions.json`
  пуст и руками не правится: `npm run lint` не даёт ему наполниться.
- Тест, запускающий процесс CLI или git, добавляется в список `processTests` в
  `vitest.config.ts`: такие тесты идут отдельным проектом без параллельности.
- Мёртвого кода нет: неиспользуемое удаляется, `knip` в `npm run check` это проверяет.
- Хуки: перед коммитом — линтер и секреты; перед отправкой — `npm run check`.
- Секреты проверяет `gitleaks` через `scripts/gitleaks-if-present.mjs`. Если
  бинаря нет, хук завершается ненулевым кодом и называет страницу установки
  https://github.com/gitleaks/gitleaks. Чтобы пропустить проверку, задайте
  `QA_RUN_TRIAGE_SKIP_SECRET_SCAN=1` — скрипт напечатает, что скан пропущен этой
  переменной, и завершится кодом 0.
- Красный хук не обходится `--no-verify`; чинится причина.

## Правила работы

- Непонятно — спросить владельца до работы, простым языком.
- Задача выполняется как поставлена, без своих оптимизаций и шагов в сторону.
- Заметное для пользователя изменение дописывается в раздел «Не выпущено» файла
  `CHANGELOG.md` тем же коммитом.
- Коммит — одна строка, без следов ассистентов.
- Публикацию пакета агент не выполняет: выпуск запускает человек, порядок ниже.

## Выпуск версии

Вкладка Actions на GitHub → workflow «Release» → выбрать patch, minor или major. Дальше
ручных шагов нет: сервер прогоняет полную проверку, повышает версию, переносит раздел
«Не выпущено» файла `CHANGELOG.md` в раздел с номером и датой, записывает номер версии в
файл скилла, отправляет коммит и метку в репозиторий, публикует пакет в npm и создаёт
запись на странице GitHub Releases с текстом раздела.

Метка уходит в репозиторий до публикации: неудачную публикацию можно повторить, а
опубликованную версию отозвать нельзя. Пустой раздел версии в `CHANGELOG.md` останавливает
выпуск до отправки метки. Права на публикацию подтверждает доверенная публикация npm
(OIDC), постоянного токена в секретах нет. Разовая настройка на npmjs.com: карточка пакета →
Settings → Trusted Publisher → GitHub Actions, владелец `rizias`, репозиторий
`qa-run-triage`, workflow `release.yml`.

## Данные в репозитории

Реальных данных стенда и компании в репозитории не бывает: токены, cookies, адреса и домены
стендов, учётные записи, идентификаторы пользователей, телефоны, почта, номера задач
трекера, чужие и личные пути. Относится к коду, тестам, фикстурам и документации.
Фикстуры делаются из реальных отчётов только после обезличивания: запрещённые значения
заменяются постоянными заглушками, а числа, которые проверяют тесты, не меняются.

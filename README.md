# qa-run-triage

`qa-run-triage` помогает инженеру разбирать прогоны автотестов с сервера CI: скачивает данные
конкретного билда в локальный кэш, показывает сводку и падения, читает исходник теста из этого
билда и хранит историю разборов. Инструмент обращается к серверу CI только на чтение: он не
запускает прогоны и ничего не удаляет на сервере прогонов.

Сегодня поддержан только сервер CI вида `jenkins`; прогоны из GitHub Actions, GitLab CI и
других систем инструмент не читает.

## Установка

Нужен Node.js 22 или новее (действующие LTS-версии — 22 и 24).

```bash
npm install --global @rizias/qa-run-triage
```

Пакет устанавливает одну команду — `qa-run-triage`.

## Быстрый старт

```bash
qa-run-triage config init
```

Команда создаёт настройки профиля `default`. До первого сетевого запроса заполните
`~/.qa-run-triage/profiles/default/profile.json`: адрес в `servers.main.baseUrl`,
при нескольких серверах — сервер джобы в `defaultServer` или `jobs`. Выберите
`servers.main.auth`: `none`, `basic` (по умолчанию) или `token`. Для `basic` задайте
`main.proxyUser` и `main.proxyPass` в соседнем `credentials.json`, для `token` —
`main.user` и `main.token`; для `none` запись секретов не нужна.
Полный пример приведён в [настройках](docs/settings.md).

После сохранения настроек подключения:

```bash
qa-run-triage runs folder/example-job
```

## Настройка

Профиль — один контур: одна компания или один отдел со всеми его серверами, стендами и
репозиториями. Второй сервер CI внутри того же контура — ещё одна запись
в `servers`, а не новый профиль; второй профиль заводят под другой контур — другой заказчик,
другой отдел со своим журналом и отчётом. Данные лежат в домашней папке пользователя, в
Windows это `C:\Users\<имя>\.qa-run-triage\`:

```
~/.qa-run-triage/
  config.json                   общий файл: текущий профиль и привязки папок
  skills-registry.json          где стоят копии скилла, общий для всех профилей
  profiles/
    default/
      profile.json               настройки контура: серверы, группы джоб, пределы
      credentials.json           секреты серверов контура
      notes.md                   заметки агента об инфраструктуре, если завели
      cache/                    скачанные прогоны, журнал, отчёт, составы прогонов
    team-b/
      ...
```

Профиль по умолчанию называется `default`. В самом проекте конфигурационных файлов нет.

```bash
qa-run-triage config init
qa-run-triage config init --profile team-b
```

Команда создаёт общий файл, если его ещё нет (с `profile`, равным `default`), каталог
выбранного профиля, в нём `profile.json` с необязательными полями и их значениями по
умолчанию и пустой `credentials.json`. Адрес сервера и секреты она не пишет — их вписывают
руками; существующие файлы команда не трогает.

Минимальный случай — один сервер контура: `defaultServer` и `jobs` не нужны, единственный
сервер в `servers` сам становится сервером по умолчанию.

`profile.json`:

```json
{
  "servers": {
    "main": {
      "kind": "jenkins",
      "auth": "basic",
      "baseUrl": "https://ci.example"
    }
  }
}
```

`credentials.json`:

```json
{
  "main": { "proxyUser": "reader-example", "proxyPass": "пример-пароля" }
}
```

Режим аутентификации сервера задаёт поле `auth`: `none`, `basic` (по умолчанию) или `token`;
режимы и поля секретов — [docs/settings.md](docs/settings.md), раздел «Аутентификация сервера».
Учётные данные для `credentials.json`: логин и пароль прокси (`proxyUser`, `proxyPass`) выдаёт
администратор CI; API-токен Jenkins (`user`, `token`) пользователь создаёт сам: в Jenkins нажать
на своё имя справа вверху → Configure → API Token → Add new token; токен показывается один раз.
Проверка: `qa-run-triage runs <джоба>` отвечает списком прогонов; ошибка 401 значит, что
учётные данные неверны.


Полный пример с двумя серверами и таблица числовых пределов — [docs/settings.md](docs/settings.md).

Общий файл `config.json` в корне `~/.qa-run-triage` называет текущий профиль и, необязательно,
привязки папок к профилям:

```json
{
  "profile": "default",
  "bindings": {
    "/home/me/clones/backend-tests": "team-b"
  }
}
```

Три файла и что в них:

| Файл | Что в нём |
|---|---|
| `config.json` (корень `~/.qa-run-triage`) | `profile` — имя текущего профиля; `bindings` — необязательный словарь «путь папки → профиль» |
| `profile.json` (в каталоге профиля) | `description`, `servers`, `defaultServer`, `repos`, `environment`, `jobs`, `allowedJobs`, `limits`, `report` |
| `credentials.json` (в каталоге профиля) | секреты по имени сервера: `proxyUser` и `proxyPass` для `basic`, `user` и `token` для `token` |

Блоки `profile.json`:

| Блок | Что в нём | Где взять значение |
|---|---|---|
| `description` | краткое описание контура, печатается командой `config profiles` | придумать самим, одна строка |
| `servers` | словарь серверов контура: имя → `kind` (пока только `jenkins`, оно же по умолчанию), `auth` — режим `none`, `basic` (по умолчанию) или `token`, `baseUrl` — адрес сервера CI (при необходимости через прокси, например `https://jenkins.example`), обязателен для сетевых команд, `reportArtifact` — имя артефакта билда с отчётом Allure, по умолчанию `allure-report.zip`, `workspaceNodeMax` — для kind `jenkins`: до какого номера узла ищется рабочий каталог, по умолчанию 40 | `baseUrl` — адрес Jenkins из адресной строки браузера до первого `/job/`; если перед Jenkins прокси — адрес прокси у администратора CI. `auth` — у администратора CI: без входа, логин и пароль прокси или логин Jenkins с API-токеном |
| `defaultServer` | имя сервера из `servers`, который используют джобы без совпавшей записи в `jobs`; обязателен, когда в `servers` больше одной записи, при ровно одном сервере это он и есть | имя одного из `servers` |
| `repos` | список абсолютных путей локальных клонов git с кодом автотестов; список может быть пустым | пути к своим клонам; адрес репозитория виден в консольном логе прогона в строке checkout |
| `environment` | из каких параметров билда брать окружение `env` и город `city` записи журнала, первый найденный параметр в списке; одно на весь профиль, без переопределения на джобу | имена параметров билда — в выводе `summary`, поле `parameters` |
| `jobs` | маршрутизация джоб на сервер группами. Ключ — полное имя джобы или папка джоб; сравнение без учёта регистра, как у `allowedJobs`; действует самое длинное совпадение. У группы обязательно одно свойство: `server` — имя сервера из `servers`. Ключ `*` — ошибка с полем `jobs.*`, он не особый | имена джоб и папок — командой `jobs` |
| `allowedJobs` | список разрешённых джоб; пустой список или отсутствие поля разрешают все | имена джоб — командой `jobs`; чаще всего не нужен |
| `limits` | числовые пределы, таблица в [docs/settings.md](docs/settings.md) | умолчания подходят, менять при необходимости |
| `report` | `timeZone` — часовой пояс IANA для дат и архива отчёта; по умолчанию пояс машины, `config init` записывает его в профиль | пояс IANA своей команды, например `Europe/Berlin`; без поля — пояс машины |

Скалярные поля перекрываются переменными окружения `QA_RUN_TRIAGE_*`; переменная важнее файла,
файл важнее умолчания. Таблица переменных — [docs/settings.md](docs/settings.md), раздел
«Переменные окружения».

Неизвестное поле, значение неверного типа и число вне диапазона завершают команду ошибкой с
именем поля и путём файла.

Профиль выбирается в таком порядке, действует первый заданный источник: `--config <путь>` →
`--profile <имя>` → переменная `QA_RUN_TRIAGE_PROFILE` → привязка папки из `bindings` →
поле `profile` общего файла → профиль `default`. Профиль или файл, указанный явно, обязан
существовать. Полный порядок, вывод команды `config`/`config --json`
и граница доступа `allowedJobs` — [docs/settings.md](docs/settings.md).

```bash
qa-run-triage config profiles
qa-run-triage config use team-b
```

## Командная строка

Во всех примерах `folder/example-job` — полное имя джобы, а `42` — номер билда. Любая команда
принимает флаги `--profile <имя>` с профилем и `--config <путь>` с произвольным файлом настроек.

| Команда | Назначение |
|---|---|
| `qa-run-triage runs folder/example-job [limit]` | Показать последние прогоны. По умолчанию `limit` равен `limits.runListDefault` (20). Без джобы, нецелый или неположительный `limit`, `limit` больше `limits.runListMax` — ошибка использования. |
| `qa-run-triage record-runs folder/example-job` | Добавить в журнал ещё не записанные успешные прогоны, дозаполнить известное окружение старых записей и вернуть список прогонов, которым нужен разбор — уже разобранные (запись в журнале с непустым вердиктом) в список не попадают, их число видно в ответе полем «разобрано ранее». |
| `qa-run-triage fetch folder/example-job 42 [--force]` | Скачать метаданные, консольный лог, Allure-отчёт и доступные исходники в кэш. Без `--force` уже скачанный прогон возвращается из кэша. |
| `qa-run-triage source folder/example-job 42 com.example.ExampleTest` | Прочитать код теста из исходников прогона. Идентификатор — имя класса Java, который ищется в `src/main/java` и `src/test/java`, или путь к файлу относительно корня репозитория, например `packages/app/e2e/tests/login.test.ts:12:5` из поля `testFile`; хвост `:строка:столбец` отбрасывается и у пути, и у имени класса. Абсолютный путь, буква диска, обратный слэш, управляющий символ и сегменты пустой / `.` / `..` — ошибка до чтения архива и `git show`. Если архива прогона нет в кэше, файл ищется среди клонов из `repos`, чьё происхождение совпадает с одним из checkout'ов прогона (репозиторий и коммит из консольного лога); битая запись `repos` не обрывает остальные клоны и попадает в итоговую ошибку; односегментное сохранённое имя совпадает, только если последний сегмент уникален среди `repos`, иначе причина называет имя неоднозначным. Сбой git, кроме отсутствия файла в коммите, не выдаётся как «файла нет». Источник, репозиторий и коммит видны в ответе. |
| `qa-run-triage summary folder/example-job 42` | Показать сводку скачанного прогона: статусы тестов, повторы, новые и известные падения, параметры билда целиком и метаданные. Параметры билда печатаются полностью, включая значения. |
| `qa-run-triage failures folder/example-job 42 [--recovered]` | Показать падения и поломки; с `--recovered` — тесты, прошедшие после повторной попытки. У тестов Java заполнены `testClass` и `testMethod`, у тестов Playwright — `testFile` и `testLine`. Без джобы, в том числе `failures --recovered`, — ошибка использования, называющая джобу. Без целого номера билда, в том числе `failures <джоба> --recovered`, — ошибка использования, называющая аргумент билда. То же для `fetch`, `source` и `summary`. Лишний токен после аргументов `fetch`, `source`, `runs`, `summary` и `failures` — ошибка использования. |
| `qa-run-triage report [--out-dir <каталог>] [--window-days <дни>]` | Собрать HTML-отчёт из журнала. По умолчанию каталог — `journal-report` внутри `cacheDir`, окно главной страницы — 14 дней. Подробности — [docs/report.md](docs/report.md). |
| `qa-run-triage jobs [папка]` | Показать джобы и папки сервера CI. |
| `qa-run-triage query "текст ошибки" [дней]` | Показать, сколько раз и в каких прогонах встречался этот текст. Без аргумента дней окно поиска равно `limits.fingerprintLookbackDays` (по умолчанию 30). Нецелое или неположительное число дней — ошибка использования, называющая аргумент дней. |
| `qa-run-triage journal-append` | Записать разбор в журнал и пересобрать отчёт. Объект JSON подаётся на стандартный ввод, схема и примеры — [docs/journal.md](docs/journal.md). |
| `qa-run-triage config [--json]` | Показать, какой файл настроек прочитан, значение и источник каждого поля. Пароль не печатается. С `--json` — один объект JSON. |
| `qa-run-triage config init [--profile <имя>]` | Создать общий файл (если его ещё нет), каталог профиля, `profile.json` с необязательными полями по умолчанию и пустой `credentials.json`; существующие файлы не трогаются. Вместе с `--config` — ошибка использования. |
| `qa-run-triage config profiles` | Показать профили из `profiles/`, выбранный отмечен. |
| `qa-run-triage config use <имя>` | Записать имя профиля в общий файл — текущим он станет для команд без флага и переменной. |
| `qa-run-triage init` | Установить скиллы пакета агентам: выбор мест, подтверждение, запись мест в реестр. |
| `qa-run-triage update` | Обновить сам пакет до последней версии через npm. О вышедшей новой версии инструмент сообщает сам: не чаще раза в сутки он сверяется с реестром npm в фоне. |
| `qa-run-triage repair` | Починить журнал по данным кэша: убрать дубли, дозаполнить метаданные и пересчитать подписи ошибок. Прогоны различаются по серверу, джобе и билду; чужой кэш не используется. Пустой отчёт подтверждается сводкой Allure. При изменении создаётся `journal.jsonl.bak-<UTC timestamp>`; строки с неверными типами сохраняются буквально, ошибка состава одной записи не прерывает остальные. **HTML-отчёт `repair` не пересобирает** — после него для обновления отчёта нужно явно выполнить `qa-run-triage report`. |

Если команда падает, в стандартный поток ошибок сначала идёт сообщение, затем каждое звено
причины на своей строке с префиксом `Причина: `.

Ошибки `credentials.json` не показывают содержимое файла или исходную цепочку причин:
для неверного JSON указываются путь и позиция. `source` требует идентификатор теста;
файлы JavaScript и TypeScript распознаются и без каталога. Название после `#` или ` › `
отделяется до проверки безопасности пути, поэтому обратный слэш в названии допустим.
Превышение `limits.archiveMaxBytes` у ZIP рабочего каталога завершает команду ошибкой.

`fetch` сохраняет запрошенный билд и самые новые по номеру остальные прогоны джобы
до общего предела `limits.cacheKeepRuns` (по умолчанию 20), не считая прогонов со старым каталогом `sources/`: они не удаляются и не
увеличивают этот предел для остальных. Журнал и поколения HTML-отчёта эта очистка не затрагивает.

## Контракт вывода и коды возврата

Успешная команда завершается кодом возврата 0; результат — объект JSON или короткое сообщение —
печатается в стандартный поток вывода. Любая ошибка — сетевая, использования команды, схемы
настроек или схемы `journal-append` — завершает процесс кодом возврата 1. Сообщение об ошибке и,
если у неё есть цепочка причин, каждое звено этой цепочки строкой `Причина: `, печатаются в
стандартный поток ошибок. Предупреждения (например, у `repair` — про запись, которую не удалось
починить) тоже идут в стандартный поток ошибок.

Пример:

```bash
$ qa-run-triage config --config /нет/такого.json
Файл профиля /нет/такого.json не найден.
```

## Первые ошибки

- **Не задан адрес сервера.** Сообщение начинается с `Не заданы обязательные настройки сервера`
  и называет переменную окружения и поле `servers.<имя>.baseUrl` файла профиля. Впишите
  `baseUrl` в `profile.json` или задайте переменную `QA_RUN_TRIAGE_SERVER_<ИМЯ>_BASE_URL`.
- **Не заданы секреты.** Сообщение называет сервер, режим и недостающие поля:
  `proxyUser` / `proxyPass` для `basic`, `user` / `token` для `token`, а также соответствующие
  переменные `QA_RUN_TRIAGE_SERVER_<ИМЯ>_PROXY_USER` / `_PROXY_PASS` или `_USER` / `_TOKEN`.
  Впишите значения в `credentials.json` профиля или задайте переменные.
- **Неверный часовой пояс.** Ошибка называет `report.timeZone`. Укажите поддерживаемый пояс
  IANA, например `Etc/UTC`, в профиле или `QA_RUN_TRIAGE_REPORT_TIME_ZONE`.
- **Джоба вне `allowedJobs`.** Сообщение начинается с `Джоба <имя> запрещена настройкой
  allowedJobs файла настроек` и перечисляет разрешённые джобы. Добавьте джобу в `allowedJobs`
  профиля или уберите ограничение, если оно не нужно.
- **Несколько серверов без `defaultServer`.** Сообщение начинается с `Файл профиля <путь>: поле
  defaultServer обязательно, когда servers содержит больше одной записи`. Впишите
  `defaultServer` в `profile.json`, указав имя из `servers`, даже если каждой группе в `jobs` уже назначен сервер.

## Скилл

Агент пользуется теми же командами, что и человек. Порядок разбора описывает скилл, который
едет вместе с пакетом: `skills/qa-run-triage/SKILL.md`.

```bash
qa-run-triage init
```

Команда спрашивает, куда ставить — глобально для всех агентов машины, только в текущий
проект или в указанный путь, — показывает полный список путей и ставит после подтверждения.
Места установки запоминаются в `~/.qa-run-triage/skills-registry.json`; при обновлении
пакета установленные копии обновляются сами при следующем запуске любой команды. Файлы,
добавленные рядом со скиллом вручную, не трогаются.

Типичный разбор:

```bash
qa-run-triage record-runs folder/example-job
qa-run-triage fetch folder/example-job 42
qa-run-triage summary folder/example-job 42
qa-run-triage failures folder/example-job 42
qa-run-triage source folder/example-job 42 com.example.ExampleTest
qa-run-triage journal-append < разбор.json
```

Последняя команда записывает разбор и тут же пересобирает HTML-отчёт.

## Чего инструмент не делает

Обращается к серверу CI только на чтение: не запускает прогоны и ничего не удаляет на сервере
прогонов. Не читает прогоны из GitHub Actions, GitLab CI и других систем CI — только `jenkins`.

## Где что лежит

| Файл | На какой вопрос отвечает |

| `README.md` | что это и как этим пользоваться |

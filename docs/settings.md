# Настройки — подробности

Общие сведения — в README, раздел «Настройка». Здесь — полный пример профиля с двумя
серверами, таблица числовых пределов, ошибки полей, полный порядок выбора
профиля и вывод команды `config`.

Ошибки чтения JSON файла секретов показывают только путь и позицию, включая файл,
ошибочно выбранный через `--config` вместо профиля. Неизвестные ключи и значения
секретного файла не входят в диагностику. URL подключения со встроенными именем
пользователя или паролем отвергается при разрешении настроек; учётные данные
задаются отдельно. При выводе URL userinfo маскируется.

## Полный пример: контур с двумя серверами

Полный файл `profile.json` — контур с двумя серверами:

```json
{
  "description": "Команда Web — все серверы и стенды",
  "servers": {
    "main": {
      "kind": "jenkins",
      "auth": "basic",
      "baseUrl": "https://ci.example",
      "reportArtifact": "allure-report.zip"
    },
    "ui": {
      "kind": "jenkins",
      "auth": "token",
      "baseUrl": "https://ci.example",
      "reportArtifact": "allure-report.zip"
    }
  },
  "defaultServer": "main",
  "repos": [
    "/home/me/clones/backend-tests",
    "/home/me/clones/ui-tests"
  ],
  "environment": { "env": ["env", "STAND"], "city": ["city"] },
  "jobs": {
    "Playwright": { "server": "ui" }
  },
  "allowedJobs": ["backend/example-job"],
  "limits": { "cacheKeepRuns": 20 }
}
```

`environment` называет, в каких параметрах билда искать значения `env` и `city`: имя
параметра берётся из ответа `summary` (поле `parameters`), где стенд обычно виден по имени.

## Аутентификация сервера

Где взять значения: режим и, при необходимости, логин и пароль прокси (`proxyUser`,
`proxyPass`) — у администратора CI. API-токен Jenkins (`user`, `token`) пользователь создаёт
сам: в Jenkins нажать на своё имя справа вверху → Configure → раздел API Token → Add new
token; токен показывается один раз, его сразу вписывают в `credentials.json`. Проверка:
`qa-run-triage runs <джоба>` отвечает списком прогонов; ответ 401 означает неверные учётные
данные, ответ 403 — верные, но без прав на джобу.

`servers.<имя>.auth` задаёт режим; `QA_RUN_TRIAGE_SERVER_<ИМЯ>_AUTH` перекрывает файл.
Допустимы только `none`, `basic` и `token`. При отсутствии настройки действует `basic`,
поэтому профиль без этого поля работает в режиме `basic`. `config init` записывает `auth: "basic"`.

| Режим | Обязательные поля записи сервера в `credentials.json` | Заголовок запроса |
|---|---|---|
| `none` | нет; файл и запись сервера необязательны | `Authorization` отсутствует |
| `basic` | `proxyUser`, `proxyPass` | HTTP Basic с парой `proxyUser:proxyPass` |
| `token` | `user`, `token` | HTTP Basic с парой `user:token`, схема API-токена Jenkins |

Для примера выше соседний `credentials.json` имеет вид:

```json
{
  "main": { "proxyUser": "пример-пользователя", "proxyPass": "пример-пароля" },
  "ui": { "user": "пример-пользователя", "token": "пример-токена" }
}
```

Секреты перекрываются переменными `QA_RUN_TRIAGE_SERVER_<ИМЯ>_PROXY_USER`, `_PROXY_PASS`,
`_USER` и `_TOKEN` соответственно. Для `basic` и `token` пустое обязательное значение
останавливает сетевую команду; ошибка называет сервер, режим, поле и переменную.
Поля другого режима из файла или окружения отклоняются даже при пустом значении.
В `none` вся запись сервера в корректном JSON и переменные секретов игнорируются без
ошибки. Неизвестные ключи секретного файла в остальных режимах отклоняются без раскрытия
их текста. Названия `proxyUser` и `proxyPass` сохранены для совместимости:
наличие прокси не требуется.

## Часовой пояс отчёта

`report.timeZone` — строка с часовым поясом IANA, например:

```json
{ "report": { "timeZone": "Etc/UTC" } }
```

`QA_RUN_TRIAGE_REPORT_TIME_ZONE` перекрывает файл. Если настройка отсутствует, используется
`Intl.DateTimeFormat().resolvedOptions().timeZone` машины сборки.
`config init` записывает этот пояс вместе с остальными умолчаниями.
Пояс проверяется через `Intl.DateTimeFormat`; неверный тип, пустая строка и неизвестный
пояс дают ошибку с полем `report.timeZone`. Настройка действует на даты, подписи и
распределение прогонов по месяцам, в том числе при пересборке из `journal-append`.

## Переменные окружения

Поля серверов, секреты, пределы, `report.timeZone`, каталог данных и профиль перекрываются переменной окружения;
у `description` и остальных полей файла переменной нет. Переменная важнее файла, файл важнее
умолчания. Отсутствующая переменная означает «не задано», пустая считается значением.
Поля сервера и секреты сервера получают переменную по его имени:
`QA_RUN_TRIAGE_SERVER_<ИМЯ>_<ПОЛЕ>`, где имя сервера записано заглавными буквами, а всё, кроме
латинских букв и цифр, заменено на `_`; переменные читаются только для серверов, объявленных
в `servers`. Два имени, которые после замены совпадают (`foo-bar` и `foo_bar`), — ошибка с
обоими именами. Например, сервер `ci-main` даёт `QA_RUN_TRIAGE_SERVER_CI_MAIN_BASE_URL`:

| Поле | Переменная окружения |
|---|---|
| `servers.<имя>.kind` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_KIND` |
| `servers.<имя>.auth` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_AUTH` |
| `servers.<имя>.baseUrl` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_BASE_URL` |
| `servers.<имя>.reportArtifact` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_REPORT_ARTIFACT` |
| `servers.<имя>.workspaceNodeMax` (kind `jenkins`) | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_WORKSPACE_NODE_MAX` |
| `<имя>.proxyUser` из `credentials.json` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_PROXY_USER` |
| `<имя>.proxyPass` из `credentials.json` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_PROXY_PASS` |
| `<имя>.user` из `credentials.json` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_USER` |
| `<имя>.token` из `credentials.json` | `QA_RUN_TRIAGE_SERVER_<ИМЯ>_TOKEN` |
| `report.timeZone` | `QA_RUN_TRIAGE_REPORT_TIME_ZONE` |
| каталог данных, в файле его нет | `QA_RUN_TRIAGE_CACHE_DIR` |
| профиль | `QA_RUN_TRIAGE_PROFILE` |

## Числовые пределы

Пределы имеют значения по умолчанию, задаются в блоке `limits` и перекрываются переменными
окружения:

| Поле | Переменная | По умолчанию | Что задаёт |
|---|---|---|---|
| `cacheKeepRuns` | `QA_RUN_TRIAGE_CACHE_KEEP_RUNS` | 20 | сколько обычных прогонов джобы остаётся в кэше: запрошенный и самые новые остальные; прогоны с `sources/` не считаются и не удаляются |
| `reportWindowDays` | `QA_RUN_TRIAGE_REPORT_WINDOW_DAYS` | 14 | окно главной страницы отчёта, дней |
| `fingerprintLookbackDays` | `QA_RUN_TRIAGE_FINGERPRINT_LOOKBACK_DAYS` | 30 | окно поиска повторов текста ошибки, дней; источник значения, когда `query` вызвана без аргумента дней |
| `requestTimeoutMs` | `QA_RUN_TRIAGE_REQUEST_TIMEOUT_MS` | 30000 | таймаут обычного запроса к серверу CI |
| `downloadTimeoutMs` | `QA_RUN_TRIAGE_DOWNLOAD_TIMEOUT_MS` | 120000 | таймаут скачивания артефакта |
| `runListDefault` | `QA_RUN_TRIAGE_RUN_LIST_DEFAULT` | 20 | сколько прогонов возвращает список по умолчанию |
| `runListMax` | `QA_RUN_TRIAGE_RUN_LIST_MAX` | 50 | верхний предел аргумента `limit` у `runs`; большее значение — ошибка использования |
| `journalLockTimeoutMs` | `QA_RUN_TRIAGE_JOURNAL_LOCK_TIMEOUT_MS` | 5000 | сколько ждать освобождения журнала |
| `journalLockPollMs` | `QA_RUN_TRIAGE_JOURNAL_LOCK_POLL_MS` | 20 | шаг опроса замка журнала |
| `archiveMaxBytes` | `QA_RUN_TRIAGE_ARCHIVE_MAX_BYTES` | 2147483648 | суммарный несжатый размер одного архива при распаковке, считается по фактически прочитанным байтам потока, а не по заявленному в архиве значению; больше — ошибка, частичная распаковка в каталоге прогона не остаётся |
| `journalInputMaxBytes` | `QA_RUN_TRIAGE_JOURNAL_INPUT_MAX_BYTES` | 1048576 | размер объекта JSON на стандартном вводе команды `journal-append`; больше — чтение останавливается, запись в журнал не выполняется |

## Ошибки полей

Неизвестное поле общего файла — ошибка с именем поля и путём файла.
`config init` вместе с `--config` — ошибка использования:
создание работает только с профилями. Ключи `bindings` — абсолютные пути; на Windows — с
буквой диска или UNC, не ведущий `/`; относительный ключ — ошибка с этим ключом. Если для
джобы нет сервера, ошибка называет джобу и поля
`jobs.<ключ>.server` и `defaultServer`.

## Выбор профиля — источники и вывод `config`

Профиль выбирается в таком порядке, действует первый заданный источник:

1. `--config <путь>` любой команды — читает конкретный файл `profile.json`, его каталог
   считается каталогом профиля, файл секретов ищется рядом.
2. `--profile <имя>`.
3. переменная `QA_RUN_TRIAGE_PROFILE`.
4. привязка папки — запись в `bindings` общего файла: самое длинное совпадение абсолютного
   пути текущей папки по границе сегмента пути, в Windows без учёта регистра.
5. поле `profile` общего файла.
6. профиль `default`.

Профиль или файл, указанный явно флагом, переменной или общим файлом, обязан существовать.

```bash
qa-run-triage config profiles
qa-run-triage runs folder/example-job --profile team-b
```

Команда `config use <имя>` записывает имя существующего профиля в общий файл — дальше, без
флагов и переменной, команды читают его:

```bash
qa-run-triage config use team-b
```

Привязка папки закрепляет профиль за каталогом проекта, чтобы не указывать `--profile` в
каждой команде:

```json
{
  "profile": "default",
  "bindings": {
    "/home/me/clones/backend-tests": "team-b"
  }
}
```

Что прочиталось и откуда, показывает команда:

```bash
qa-run-triage config
```

Печатает путь общего файла, текущий профиль и чем он выбран (`flag`, `env`, `binding`,
`config` или `default`), пути `profile.json`, `credentials.json` и `notes.md` с признаками
наличия, каждое поле со значением и источником `env`, `file` или `default`, включая серверы,
группы джоб `jobs`, `environment`, `report.timeZone` и режим `auth` каждого сервера;
секреты серверов — только отметкой «задан» или «не задан» для полей выбранного режима,
без значения. Для `none` признаков секретов нет. Пустой секрет из переменной показан как заданный с источником `env`. Если сервер
один и `defaultServer` в файле нет, показано его имя с источником `default`.
`qa-run-triage config --json` выдаёт то же одним объектом JSON в неизменном порядке полей;
верхнеуровневые ключи: `commonFile`, `commonFileFound`, `profileName`, `profileSource`,
`profileFile`, `profileFileFound`, `credentialsFile`, `credentialsFileFound`, `notesFile`,
`notesFileFound`, `description`, `servers`, `jobs`, `defaultServer`, `repos`, `environment`,
`allowedJobs`, `report`, `limits`, `cacheDir`. В `report` поле `timeZone` содержит значение и источник. `notesFile` — путь `notes.md` текущего профиля.
`qa-run-triage config profiles` печатает имена профилей из `profiles/` с их описанием,
текущий отмечен с указанием, чем выбран. Профиль, чей `profile.json` не читается, печатается
с пометкой «не прочитано» и причиной и не обрывает список. На Windows ключ `bindings` —
путь с буквой диска или UNC, не ведущий `/`. `config use` и `config profiles` работают, даже
если указатель текущего профиля сломан; на POSIX `config use` сохраняет права 0600 у общего
файла. Заметки инструмент не читает: в них агент по вашему слову хранит знания об
инфраструктуре, которых нет в отчётах.

Без сервера CI работают команды `report`, `repair`, `query` и `journal-append` — им нужен только
каталог данных; `config`, `init` и `update` не читают ни сервер прогонов, ни каталог данных.

`allowedJobs` — граница доступа: команды отказываются работать с джобой вне `allowedJobs` — и
сетевые, и читающие кэш. Сравнение не зависит от регистра, крайние пробелы и `/` отбрасываются.
Папки, внутри которых находятся разрешённые джобы, доступны для обхода автоматически. Команды
`report` и `repair` работают с журналом целиком и джобу не принимают.
# Имена артефактов и пути скиллов

`servers.<имя>.reportArtifact` — простое непустое имя файла без слэшей, `..`,
диска и управляющих символов. Это проверяется и для переменной окружения.
Недопустимые пути копий и файлов в реестре скиллов пропускаются с сообщением
до записи или удаления; разрешены только пути внутри каталогов скиллов агентов.

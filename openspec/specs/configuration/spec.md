# Настройки и данные Specification

## Purpose

Учётные данные к Jenkins и все данные разбора живут в одном месте в домашней папке пользователя. В репозитории инструмента конфигурационных файлов нет — это защищает и от утечки, и от расхождения настроек между машинами.

## Requirements

### Requirement: Ошибки секретного файла не раскрывают содержимое

Ошибка JSON в `credentials.json` SHALL сообщать только путь и позицию, без фрагментов содержимого и исходной цепочки причин. Остальные ошибки чтения и проверки секретного файла MUST NOT включать его значения или неизвестные ключи. Это правило SHALL действовать и когда через `--config` вместо файла профиля ошибочно передан файл секретов.

#### Scenario: Неверный JSON содержит секрет

- WHEN секрет записан без кавычек или попал в неизвестный ключ
- THEN диагностика и цепочка причин не содержат его текста

#### Scenario: Секретный файл выбран как профиль

- WHEN через `--config` выбран файл с содержимым секретов вместо профиля
- THEN команда завершается безопасной ошибкой без значений и неизвестных ключей файла

### Requirement: Адрес подключения не содержит учётных данных

Разрешение `baseUrl` SHALL отвергать URL с userinfo до создания клиента, называя поле либо переменную без значения и исходной причины. Вывод `config`, ошибки и журналы MUST NOT раскрывать userinfo URL; при форматировании адреса userinfo SHALL маскироваться.

#### Scenario: Учётные данные в адресе из окружения

- WHEN адрес сервера из файла или окружения содержит имя пользователя либо пароль
- THEN разрешение конфигурации завершается ошибкой с именем поля или переменной без учётных данных

### Requirement: Допустимые имена серверов сохраняются в словаре

Словари серверов и секретов SHALL сохранять все допустимые имена, включая `__proto__`, как собственные записи.

#### Scenario: Имя совпадает со свойством прототипа

- WHEN профиль объявляет сервер `__proto__`
- THEN сервер доступен при проверке и разрешении настроек

### Requirement: Артефакт отчёта является именем файла

При загрузке настроек `servers.<имя>.reportArtifact` SHALL проверяться как непустое простое имя файла: без разделителей путей, `..`, диска и управляющих символов. Проверка SHALL действовать и для значения из переменной окружения; ошибка SHALL называть поле.

#### Scenario: Путь вместо имени артефакта

- WHEN `servers.main.reportArtifact` содержит `../report.zip` или обратный слэш
- THEN загрузка конфигурации завершается ошибкой с именем `servers.main.reportArtifact`

### Requirement: Один каталог в домашней папке

Настройки и данные SHALL находиться в каталоге `.qa-run-triage` домашней папки пользователя, одинаково на всех системах. В корне лежат общий файл `config.json` и реестр копий скилла `skills-registry.json`. Каждый профиль — каталог `profiles/<имя>/` с файлом настроек `profile.json`, файлом секретов `credentials.json`, заметками `notes.md` и каталогом данных `cache/`: скачанные прогоны, журнал, отчёт, составы. Профиль — один контур: одна компания или один отдел со всеми его серверами, стендами и репозиториями. Профиль по умолчанию называется `default`.

#### Scenario: Первый запуск на новой машине

- WHEN профиль не выбран явно и каталог данных не задан переменной
- THEN используется `profiles/default/cache` внутри `.qa-run-triage` домашней папки

#### Scenario: Данные профиля

- WHEN выбран профиль `team-b`
- THEN используется `profiles/team-b/cache` внутри `.qa-run-triage` домашней папки

### Requirement: В репозитории нет конфигурационных файлов инструмента

Репозиторий MUST NOT содержать файлов настроек инструмента. Учётные данные SHALL храниться только в файле настроек пользователя и нигде больше.

#### Scenario: Проверка репозитория

- WHEN просматривается содержимое репозитория
- THEN файлов с учётными данными в нём нет

### Requirement: Переменные окружения перекрывают файл

Скалярные поля серверов, числовые пределы, часовой пояс отчёта, каталог данных и имя профиля SHALL иметь свою переменную окружения с префиксом `QA_RUN_TRIAGE_`. У полей `description`, `defaultServer`, `repos` и `environment` переменной MUST NOT быть. Поля сервера — `QA_RUN_TRIAGE_SERVER_<ИМЯ>_<ПОЛЕ>`, где имя сервера записано заглавными, а всё кроме латинских букв и цифр заменено на `_`: `kind` — `_KIND`, `auth` — `_AUTH`, `baseUrl` — `_BASE_URL`, `reportArtifact` — `_REPORT_ARTIFACT`, `workspaceNodeMax` — `_WORKSPACE_NODE_MAX` (только для kind `jenkins`), `proxyUser` — `_PROXY_USER`, `proxyPass` — `_PROXY_PASS`, `user` — `_USER`, `token` — `_TOKEN`; переменные читаются только для серверов, объявленных в `servers`. Часовой пояс отчёта — `QA_RUN_TRIAGE_REPORT_TIME_ZONE`. Каталог данных — `QA_RUN_TRIAGE_CACHE_DIR`, в файле этого поля нет; профиль — `QA_RUN_TRIAGE_PROFILE`; пределы — по таблице требования о числовых пределах, включая `journalInputMaxBytes` — `QA_RUN_TRIAGE_JOURNAL_INPUT_MAX_BYTES`. Порядок источников для каждого поля: переменная окружения, затем файл, затем значение по умолчанию. Отсутствующая переменная означает «не задано»; пустая строка SHALL считаться заданным значением и проверяться как значение. Два имени сервера, которые после этой замены дают один и тот же префикс переменных, SHALL быть ошибкой, называющей оба имени. Пустой `--profile` и пустая `QA_RUN_TRIAGE_PROFILE` SHALL быть ошибкой, называющей флаг или переменную. Пустая `QA_RUN_TRIAGE_CACHE_DIR` SHALL быть ошибкой, называющей эту переменную. Списки и словари — `allowedJobs`, `jobs`, `servers`, `bindings` — SHALL задаваться только в файле. Переменные с неизвестными именами инструмент MUST NOT читать.

#### Scenario: Файла настроек нет, переменные заданы

- WHEN файла профиля нет, а сервер `jenkins-main` объявлен только в переменных: `QA_RUN_TRIAGE_SERVER_JENKINS_MAIN_BASE_URL`, `_PROXY_USER`, `_PROXY_PASS`
- THEN сервер без объявления в `servers` переменными не создаётся, и сетевая команда завершается ошибкой, называющей джобу и поле `jobs.*.server`

#### Scenario: Переменная сервера

- WHEN сервер `jenkins-main` объявлен в `servers`, а адрес задан переменной `QA_RUN_TRIAGE_SERVER_JENKINS_MAIN_BASE_URL`
- THEN у `servers.jenkins-main.baseUrl` источник `env` и значение переменной

#### Scenario: Задано и в файле, и в переменной

- WHEN значение задано и в файле, и в переменной окружения
- THEN используется значение переменной окружения

#### Scenario: Пустая переменная

- WHEN переменная задана пустой строкой, а в файле есть значение
- THEN используется пустая строка, и для обязательного поля это ошибка «не задано» с именем переменной

#### Scenario: Два имени сервера с одним префиксом переменных — ошибка

- WHEN в `servers` есть имена `foo-bar` и `foo_bar`
- THEN чтение настроек завершается ошибкой, называющей оба имени

#### Scenario: Пустой --profile и пустые переменные профиля и каталога данных — ошибка

- WHEN задан `--profile` с пустой строкой или `QA_RUN_TRIAGE_PROFILE` равна пустой строке
- THEN команда завершается ошибкой, называющей флаг `--profile` или переменную `QA_RUN_TRIAGE_PROFILE`
- AND WHEN `QA_RUN_TRIAGE_CACHE_DIR` равна пустой строке
- THEN команда завершается ошибкой, называющей переменную `QA_RUN_TRIAGE_CACHE_DIR`

#### Scenario: Неизвестная переменная с префиксом продукта не читается

- WHEN задана неизвестная переменная с префиксом `QA_RUN_TRIAGE_`
- THEN значения настроек не изменяются

#### Scenario: journalInputMaxBytes переопределён переменной

- WHEN `QA_RUN_TRIAGE_JOURNAL_INPUT_MAX_BYTES` задана положительным целым числом
- THEN команда `journal-append` использует это значение вместо значения из файла или умолчания 1048576

### Requirement: Команда показа настроек не печатает пароль

Команда `config` SHALL печатать путь общего файла и признак его наличия; имя текущего профиля и чем он выбран: `flag`, `env`, `binding`, `config` или `default`; пути файла профиля, файла секретов и файла заметок с признаками наличия; каждое поле профиля со значением и источником `env`, `file` или `default`, включая словари `servers` и `jobs`, поле `defaultServer`, список `repos` и словарь `environment`, поле `report.timeZone`, а также каталог данных. Поля `jobs` и `environment` SHALL нести значение и источник так же, как остальные поля. Если `defaultServer` в файле нет и в `servers` ровно одна запись, `defaultServer` SHALL показывать имя этого сервера с источником `default`. У каждого сервера SHALL показываться `auth`; секреты MUST NOT печататься. Только для полей выбранного режима SHALL выводиться признак «задан» или «не задан» и источник. Секрет, заданный переменной окружения пустой строкой, SHALL показываться как заданный с источником `env`. `config --json` SHALL печатать те же данные одним объектом JSON в стандартный вывод в неизменном порядке полей; диагностика SHALL идти в стандартный поток ошибок.

#### Scenario: Пароль задан

- WHEN пароль сервера задан в файле секретов
- THEN вывод содержит у этого сервера признак «задан» и источник `file`, но не само значение

#### Scenario: Источник значения

- WHEN адрес сервера задан переменной окружения, а каталог данных нигде не задан
- THEN у адреса источник `env`, у каталога данных источник `default` и значение по умолчанию

#### Scenario: Группы джоб в выводе

- WHEN в файле профиля есть группа `Playwright` со свойством `server` и задан `defaultServer`
- THEN `config` печатает группу `Playwright` с её `server`, а также `defaultServer`, `repos` и `environment` профиля

#### Scenario: config показывает jobs, environment и defaultServer со значением и источником; пустой секрет из env задан

- WHEN команда `config` или `config --json` показывает настройки
- THEN у `jobs` и `environment` есть значение и источник, как у остальных полей
- AND если сервер один и `defaultServer` в файле нет, показано его имя с источником `default`
- AND секрет, заданный переменной пустой строкой, показан как заданный с источником `env`

### Requirement: Отсутствие обязательных настроек названо поимённо

Если для сетевой команды не заданы обязательные значения сервера, инструмент SHALL перечислить их поимённо — название переменной окружения сервера и путь поля в файле профиля или файле секретов через точку — и назвать путь этого файла.

#### Scenario: Не задан адрес Jenkins

- WHEN у сервера `main` адрес не задан ни в файле профиля, ни в переменной
- THEN ошибка называет `QA_RUN_TRIAGE_SERVER_MAIN_BASE_URL`, поле `servers.main.baseUrl` и путь файла профиля

### Requirement: Числовые пределы имеют значения по умолчанию

Числовые пределы работы и формата отчёта SHALL иметь значения по умолчанию, SHALL задаваться в блоке `limits` файла настроек и SHALL перекрываться переменными окружения: `cacheKeepRuns` — `QA_RUN_TRIAGE_CACHE_KEEP_RUNS`, 20; `reportWindowDays` — `QA_RUN_TRIAGE_REPORT_WINDOW_DAYS`, 14; `fingerprintLookbackDays` — `QA_RUN_TRIAGE_FINGERPRINT_LOOKBACK_DAYS`, 30; `requestTimeoutMs` — `QA_RUN_TRIAGE_REQUEST_TIMEOUT_MS`, 30000; `downloadTimeoutMs` — `QA_RUN_TRIAGE_DOWNLOAD_TIMEOUT_MS`, 120000; `runListDefault` — `QA_RUN_TRIAGE_RUN_LIST_DEFAULT`, 20; `runListMax` — `QA_RUN_TRIAGE_RUN_LIST_MAX`, 50; `journalLockTimeoutMs` — `QA_RUN_TRIAGE_JOURNAL_LOCK_TIMEOUT_MS`, 5000; `journalLockPollMs` — `QA_RUN_TRIAGE_JOURNAL_LOCK_POLL_MS`, 20; `archiveMaxBytes` — `QA_RUN_TRIAGE_ARCHIVE_MAX_BYTES`, 2147483648; `journalInputMaxBytes` — `QA_RUN_TRIAGE_JOURNAL_INPUT_MAX_BYTES`, 1048576. В блоке `limits` одиннадцать полей. Значение SHALL быть положительным целым числом в десятичной записи; иное — ошибка с именем поля или переменной. Замок журнала и окно главной страницы отчёта, в том числе при пересборке отчёта командой записи разбора, SHALL брать пределы уже загруженного выбранного профиля и MUST NOT заново читать профиль по умолчанию. Команда `runs` SHALL отвергать предел списка больше `runListMax` ошибкой использования, называющей этот предел и поле.

#### Scenario: Предел переопределён переменной

- WHEN окно главной страницы задано переменной окружения
- THEN отчёт использует заданное значение вместо 14 дней

#### Scenario: Предел задан в файле

- WHEN `limits.cacheKeepRuns` задан в файле настроек, а переменной нет
- THEN очистка кэша использует значение из файла

#### Scenario: Замок журнала и окно отчёта берутся из выбранного профиля

- WHEN выбран профиль с своими `limits.journalLockTimeoutMs` и `limits.reportWindowDays`, в том числе флагом `--profile` или `--config`
- THEN ожидание замка журнала и окно пересобранного отчёта используют эти значения

#### Scenario: Предел несжатого архива по умолчанию 2147483648

- WHEN предел `limits.archiveMaxBytes` ни в файле, ни в переменной не задан
- THEN действует значение 2147483648
- AND команда `config` показывает это поле, переменную `QA_RUN_TRIAGE_ARCHIVE_MAX_BYTES` и источник `default`

#### Scenario: Предел входа journal-append по умолчанию 1048576

- WHEN предел `limits.journalInputMaxBytes` ни в файле, ни в переменной не задан
- THEN действует значение 1048576
- AND команда `config` показывает это поле, переменную `QA_RUN_TRIAGE_JOURNAL_INPUT_MAX_BYTES` и источник `default`

### Requirement: Выбор файла настроек

Профиль SHALL выбираться в таком порядке, первый найденный: флаг `--config <путь>` любой команды указывает на произвольный файл профиля, его каталог считается каталогом профиля и файл секретов ищется рядом; флаг `--profile <имя>`; переменная `QA_RUN_TRIAGE_PROFILE`; привязка папки из `bindings` общего файла — самое длинное совпадение абсолютного пути текущей папки по границе сегмента, на Windows без учёта регистра; поле `profile` общего файла; профиль `default`. Имя профиля состоит из букв, цифр, дефиса и подчёркивания. Отсутствие файла `profiles/default/profile.json` MUST NOT быть ошибкой: действуют умолчания. Профиль, названный флагом, переменной, привязкой или общим файлом, или файл, указанный флагом, которого нет, SHALL быть ошибкой с полным путём; исключение — `config init`, которому разрешено его создать. Пустой `--profile` и пустая `QA_RUN_TRIAGE_PROFILE` — заданные значения и ошибка по требованию о переменных. `config init` вместе с `--config` SHALL быть ошибкой использования: создание работает только с профилями.

#### Scenario: Флаг важнее переменной

- WHEN заданы и `--config`, и `QA_RUN_TRIAGE_PROFILE`
- THEN читается файл из флага, и команда `config` показывает его путь

#### Scenario: Явный файл отсутствует

- WHEN `--config` указывает на несуществующий файл
- THEN команда завершается ошибкой с полным путём и ненулевым кодом, умолчания не применяются

#### Scenario: Профиль флагом

- WHEN задан `--profile team-b`
- THEN читается `profiles/team-b/profile.json`, и команда `config` показывает его путь

#### Scenario: Профиль из общего файла

- WHEN флага и переменной нет, привязки нет, а в общем файле `profile` равен `team-b`
- THEN читается `profiles/team-b/profile.json`, и `config` показывает, что профиль выбран общим файлом

#### Scenario: Профиля нет

- WHEN `--profile` называет имя, каталога которого нет
- THEN команда завершается ошибкой с полным путём файла профиля

#### Scenario: config init с --config — ошибка использования

- WHEN запущена `config init` вместе с `--config`
- THEN команда завершается ошибкой использования и не создаёт файлов

### Requirement: Создание файла настроек

Команда `config init` SHALL создать общий файл с `profile` равным `default`, если общего файла нет; каталог выбранного профиля; в нём `profile.json` с необязательными полями и их значениями по умолчанию: `description` пустой строкой, `servers` с одним сервером `main` из `kind` равного `jenkins`, `auth` равного `basic` и `reportArtifact`, `repos` пустым списком, `environment` умолчанием `{ "env": ["env"], "city": ["city"] }`, `allowedJobs` пустым списком, `limits` с одиннадцатью пределами, `report.timeZone` с часовым поясом машины; и `credentials.json` с пустым словарём. Полей `jobs` и `defaultServer` в созданном файле нет. Адрес сервера и секреты MUST NOT записываться; поля каталога данных в файле нет. Файлы SHALL создаваться эксклюзивно; на POSIX — с правами 0600. Существующий файл MUST NOT изменяться: команда печатает его путь и завершается кодом 0. `config init --profile <имя>` SHALL создавать профиль по тем же правилам. `config init` вместе с `--config` SHALL быть ошибкой использования.

#### Scenario: Файла нет

- WHEN `config init` запущена в пустом каталоге
- THEN созданы общий файл с `profile` равным `default`, `profiles/default/profile.json` с полями по умолчанию (включая пустой `repos` и `environment` умолчанием, без `jobs` и `defaultServer`) и `profiles/default/credentials.json` с пустым словарём; адреса и секретов в них нет

#### Scenario: Файл уже есть

- WHEN `config init` запущена повторно
- THEN файлы не изменились, код возврата 0

#### Scenario: Новый профиль

- WHEN `config init --profile team-b` запущена, а каталога профиля нет
- THEN созданы `profiles/team-b/profile.json` с полями по умолчанию и `profiles/team-b/credentials.json`; общий файл не изменён

#### Scenario: config init записывает одиннадцать пределов включая archiveMaxBytes

- WHEN `config init` создаёт `profile.json`
- THEN в `limits` ровно одиннадцать полей, среди них `archiveMaxBytes` равный 2147483648 и `journalInputMaxBytes` равный 1048576
- AND сервер по умолчанию называется `main` с `kind` равным `jenkins` и `auth` равным `basic`
- AND `report.timeZone` равен `Intl.DateTimeFormat().resolvedOptions().timeZone`

### Requirement: Ошибка настроек называет поле и способ исправить

Ошибка чтения любого из трёх файлов — общего, профиля, секретов — SHALL называть путь файла и, где применимо, поле или переменную: файл не разбирается как JSON; корень файла не объект; неизвестное поле; значение неверного типа; число вне диапазона; обязательное поле не задано; ссылка группы на сервер, которого нет в `servers`; сервер в файле секретов, которого нет в `servers`. Для обязательного поля сообщение SHALL называть оба способа задать его: переменную и поле файла.

#### Scenario: Неизвестное поле

- WHEN в файле профиля есть поле, которого нет в схеме
- THEN команда завершается ошибкой с именем поля и путём файла

#### Scenario: Неверный тип

- WHEN `allowedJobs` задан строкой, а не списком
- THEN ошибка называет поле `allowedJobs`, ожидаемый тип и путь файла

### Requirement: Список профилей

Команда `config profiles` SHALL печатать имена каталогов из `profiles/`, в которых есть `profile.json`, с описанием из поля `description`, и отмечать текущий с указанием, чем он выбран. Профиль `default` SHALL показываться, даже если его каталога ещё нет. Файл профиля, который не читается как настройки, SHALL печататься строкой `имя — (не прочитано: …)` с причиной и MUST NOT обрывать список остальных профилей.

#### Scenario: Два профиля

- WHEN в `profiles/` лежат каталоги `team-a` и `team-b` с файлами профиля
- THEN команда печатает `default`, `team-a` и `team-b` с описаниями, отмечая текущий

#### Scenario: Сломанный соседний профиль не обрывает список

- WHEN в `profiles/` есть годный профиль и соседний `profile.json`, который не разбирается как настройки
- THEN команда печатает годные имена и у сломанного — пометку, что файл не прочитан, с причиной
- AND код возврата 0

### Requirement: Файл заметок рядом с настройками

В каталоге выбранного профиля SHALL быть место для заметок агента: `notes.md`. Инструмент MUST NOT читать и создавать этот файл; команда `config` SHALL показывать его путь и признак наличия, чтобы агент нашёл его по скиллу.

#### Scenario: Заметок нет

- WHEN файла заметок нет
- THEN `config` показывает его путь и признак «нет», команды работают как прежде

### Requirement: Настройки джоб группами

Блок `jobs` SHALL быть словарём «ключ группы → настройки группы» и служит только для выбора сервера. Ключ — полное имя джобы или имя папки джоб; ключ совпадает с джобой, если равен её полному имени или началу имени до `/`; сравнение SHALL быть без учёта регистра и SHALL отбрасывать крайние пробелы и символы `/` по краям той же нормализацией, что и `allowedJobs`; при нескольких совпадениях действует самый длинный. Ключ `*` SHALL быть ошибкой, называющей поле `jobs.*`: он не является особым и MUST NOT совпадать буквально. У группы одно свойство: `server` — имя сервера из `servers`; отсутствие `server` SHALL быть ошибкой, называющей поле `jobs.<ключ>.server`. Блок задаётся только в файле; значение не словарь групп, свойство неверного типа или свойство `repo`/`environment` у группы — ошибка с путём поля.

#### Scenario: Группа папки покрывает джобы внутри

- WHEN в `jobs` есть группа `Playwright` с `server`, а джоба называется `Playwright/e2e`
- THEN для неё выбран сервер из группы `Playwright`

#### Scenario: Недостающее свойство берётся из defaultServer

- WHEN у джобы `Playwright/e2e` нет совпавшей записи в `jobs`, а в `servers` больше одного сервера
- THEN сервер джобы берётся из `defaultServer` профиля

#### Scenario: Джоба без группы и без общей группы

- WHEN ни один ключ `jobs` не совпадает с джобой, а `defaultServer` не задан, и в `servers` больше одного сервера
- THEN сетевая команда завершается ошибкой, называющей джобу и поле `defaultServer`

#### Scenario: Ключ звёздочка в jobs и группа без server — ошибка с именем поля

- WHEN в `jobs` есть ключ `*`
- THEN чтение настроек завершается ошибкой, называющей поле `jobs.*`
- AND WHEN у группы нет свойства `server`
- THEN чтение настроек завершается ошибкой, называющей поле `jobs.<ключ>.server`

#### Scenario: Ключи jobs сравниваются без учёта регистра как allowedJobs

- WHEN в `jobs` есть группа `Playwright` с `server`, а джоба записана как `playwright/e2e`
- THEN для неё выбран сервер из группы `Playwright`

### Requirement: Общий файл называет текущий профиль

В корне каталога `.qa-run-triage` SHALL лежать общий файл `config.json` с полем `profile` — именем текущего профиля — и необязательным словарём `bindings` «абсолютный путь папки → имя профиля». Ключ `bindings`, который не является абсолютным путём, SHALL быть ошибкой, называющей этот ключ. На Windows абсолютный путь SHALL означать путь с буквой диска и разделителем или UNC-путь; ключ, который начинается с `/` без буквы диска и без UNC, SHALL быть ошибкой, называющей этот ключ. Других полей в общем файле нет; неизвестное поле — ошибка с именем поля и путём файла. Отсутствие общего файла MUST NOT быть ошибкой: текущим считается `default`. Команда `config use <имя>` SHALL записывать имя существующего профиля в поле `profile`, создавая общий файл, если его нет; имя профиля, каталога которого нет, — ошибка с полным путём каталога. Запись SHALL идти через временный файл и переименование под межпроцессной блокировкой. На POSIX перезапись SHALL сохранять права 0600.

#### Scenario: Смена текущего профиля

- WHEN выполнена `config use team-b`, а каталог `profiles/team-b/` есть
- THEN общий файл содержит `profile` равный `team-b`, и следующая команда без флага читает этот профиль

#### Scenario: Профиля для смены нет

- WHEN выполнена `config use team-c`, а каталога `profiles/team-c/` нет
- THEN команда завершается ошибкой с полным путём каталога, общий файл не изменён

#### Scenario: Привязка папки

- WHEN в `bindings` есть запись для папки проекта, а команда запущена из её подпапки без флага и переменной
- THEN читается профиль из привязки, и `config` показывает, что профиль выбран привязкой

#### Scenario: Ключ bindings не абсолютный — ошибка называет ключ

- WHEN в `bindings` есть ключ, который не абсолютный путь
- THEN команда завершается ошибкой, называющей этот ключ

#### Scenario: config use сохраняет права 0600 у общего файла

- WHEN на POSIX общий файл имеет права 0600 и выполнена `config use` существующего профиля
- THEN после перезаписи права файла остаются 0600

#### Scenario: Ключ bindings на Windows без диска и UNC — ошибка

- WHEN на Windows в `bindings` есть ключ `/home/me/project`
- THEN команда завершается ошибкой, называющей этот ключ

### Requirement: Серверы профиля

Файл профиля SHALL содержать словарь `servers` «имя сервера → настройки сервера». Имя сервера состоит из букв, цифр, дефиса и подчёркивания. У сервера поля: `auth` — `none`, `basic` или `token`, по умолчанию `basic`; `kind` — поддерживаемое значение `jenkins`, оно же по умолчанию; `baseUrl` — адрес сервера CI (для kind `jenkins` — Jenkins), при необходимости через прокси, обязателен для сетевых команд; `reportArtifact` — имя артефакта отчёта Allure, по умолчанию `allure-report.zip`; `workspaceNodeMax` — до какого номера узла ищется рабочий каталог Jenkins, положительное целое, по умолчанию 40, только для kind `jenkins`. Другое значение `kind` — ошибка, перечисляющая поддерживаемые значения. Поле `workspaceNodeMax` у сервера с иным `kind` SHALL быть ошибкой, называющей поле. Файл профиля SHALL содержать поле `defaultServer` — имя сервера из `servers`; оно обязательно, когда `servers` содержит больше одной записи, и необязательно, а при отсутствии равно единственному серверу, когда запись одна. Сетевая команда с джобой SHALL брать сервер: у совпавшей записи `jobs` — её `server`; иначе `defaultServer`; иначе, если серверов несколько или серверов нет, — ошибка с именем джобы и полями `jobs.<ключ>.server` и `defaultServer`. Команда показа джоб и папок SHALL брать сервер тем же правилом: совпавшая запись `jobs` для указанной папки, иначе `defaultServer`, иначе единственный сервер; пустая папка MUST NOT требовать `defaultServer`, когда сервер один. Ссылка на сервер, которого нет в `servers` (в `jobs.<ключ>.server` или в `defaultServer`), — ошибка с путём поля.

#### Scenario: Две джобы на разных серверах

- WHEN `defaultServer` равен `main`, у группы `Playwright` в `jobs` свойство `server` равно `ui`, оба сервера есть в `servers`
- THEN прогоны `Playwright/e2e` читаются с сервера `ui`, прогоны остальных джоб — с сервера `main`

#### Scenario: Ссылка на неизвестный сервер

- WHEN у группы `Playwright` свойство `server` равно `ui`, а в `servers` такого имени нет
- THEN команда завершается ошибкой с полем `jobs.Playwright.server` и путём файла

#### Scenario: Неподдерживаемый вид сервера

- WHEN у сервера `main` поле `kind` равно `github`
- THEN команда завершается ошибкой, называющей поле `servers.main.kind` и поддерживаемое значение `jenkins`

#### Scenario: Нет сервера для джобы — ошибка называет джобу и поля jobs.<ключ>.server и defaultServer

- WHEN у джобы нет совпавшей записи в `jobs` с `server`, `defaultServer` не задан, и серверов нет или их больше одного
- THEN сетевая команда завершается ошибкой, называющей джобу и поля `jobs.<ключ>.server` и `defaultServer`

#### Scenario: jobs без папки при одном сервере не требует defaultServer

- WHEN запущена `jobs` без папки, в `servers` ровно одна запись и `defaultServer` не задан
- THEN команда выполняется с этим сервером

#### Scenario: workspaceNodeMax сервера Jenkins задаётся файлом и переменной

- WHEN у сервера `main` kind `jenkins` и задана `QA_RUN_TRIAGE_SERVER_MAIN_WORKSPACE_NODE_MAX`
- THEN `servers.main.workspaceNodeMax` берёт значение переменной
- AND WHEN поле и переменная не заданы
- THEN действует значение 40

### Requirement: Секреты живут отдельно от настроек

Секреты серверов SHALL лежать в файле `credentials.json` каталога профиля: словарь «имя сервера → поля выбранного режима аутентификации», имена те же, что в `servers`. Секрет SHALL перекрываться переменной окружения сервера. Ни одна команда MUST NOT печатать секреты; `config` показывает только признаки «задан» или «не задан» и источники полей выбранного режима. Для сетевой команды отсутствие обязательного секрета SHALL быть ошибкой с именем сервера, режимом, полем файла секретов и переменной. Имя сервера в файле секретов, которого нет в `servers`, SHALL быть ошибкой с путём файла без раскрытия неизвестного ключа.

#### Scenario: Секреты заданы в файле

- WHEN у сервера `main` в `credentials.json` заданы `proxyUser` и `proxyPass`
- THEN `config` показывает у `main` оба признака «задан» с источником `file`, значения не печатаются

#### Scenario: Секрета нет

- WHEN у сервера `main` режим `basic`, нет записи в `credentials.json` и переменные не заданы
- THEN сетевая команда с джобой сервера `main` завершается ошибкой, называющей `main`, режим `basic`, поле `main.proxyUser` файла секретов и переменную `QA_RUN_TRIAGE_SERVER_MAIN_PROXY_USER`

### Requirement: Режим аутентификации задаётся сервером

Поле `servers.<имя>.auth` SHALL принимать только `none`, `basic` или `token` и SHALL перекрываться `QA_RUN_TRIAGE_SERVER_<ИМЯ>_AUTH`. Отсутствующее поле SHALL означать `basic`, сохраняя работу прежних профилей. Неверное значение SHALL быть ошибкой с именем поля или переменной и допустимыми режимами.

#### Scenario: Прежний профиль

- WHEN поле `auth` и его переменная отсутствуют
- THEN сервер использует `basic`, а `config` показывает источник `default`

#### Scenario: Режим из окружения

- WHEN в файле `auth` равен `basic`, а переменная сервера равна `none`
- THEN запрос не требует секретов, и `config` показывает `none` с источником `env`

#### Scenario: Неподдерживаемый режим

- WHEN `servers.main.auth` или его переменная содержит неизвестный режим
- THEN ошибка называет поле или переменную и режимы `none`, `basic`, `token`

### Requirement: Доступ без аутентификации

Режим `none` MUST NOT требовать учётных данных или отправлять заголовок `Authorization`. Запись этого сервера в корректном JSON файла секретов SHALL быть необязательной; если запись присутствует, её содержимое и переменные секретов SHALL игнорироваться без ошибки. `config` MUST NOT показывать признаки секретов этого сервера.

#### Scenario: Сервер без секретов

- WHEN сервер использует `none`, а файла секретов или записи сервера нет
- THEN сетевая команда выполняет запрос без `Authorization`

#### Scenario: Остаточные секреты

- WHEN сервер использует `none`, а его запись секретов содержит поля любого режима, неизвестные поля или значения неверного типа
- THEN запись игнорируется, запрос не содержит `Authorization`, а `config` показывает только режим без признаков секретов

### Requirement: Аутентификация паролем

Режим `basic` SHALL требовать непустые `proxyUser` и `proxyPass` из `credentials.json` или переменных `_PROXY_USER` и `_PROXY_PASS` сервера. Запрос SHALL отправлять HTTP Basic с парой `proxyUser:proxyPass`. Имена этих полей SHALL сохраняться независимо от наличия прокси.

#### Scenario: Пароль задан

- WHEN сервер использует `basic` и оба поля заданы
- THEN запрос содержит `Authorization: Basic` с закодированной парой, а `config` показывает только признаки `proxyUser` и `proxyPass`

#### Scenario: Недостающее поле пароля

- WHEN у сервера `main` с режимом `basic` отсутствует `proxyUser` или `proxyPass`
- THEN ошибка называет `main`, режим `basic`, каждое недостающее поле и соответствующую переменную сервера

### Requirement: Аутентификация токеном Jenkins

Режим `token` SHALL требовать непустые `user` и `token` из `credentials.json` или переменных `QA_RUN_TRIAGE_SERVER_<ИМЯ>_USER` и `_TOKEN`. Запрос SHALL отправлять HTTP Basic с парой `user:token`.

#### Scenario: Токен задан

- WHEN сервер использует `token` и оба поля заданы, в том числе переменными поверх файла
- THEN запрос содержит `Authorization: Basic` с парой `user:token`, а `config` показывает только признаки `user` и `token` с источниками

#### Scenario: Недостающее поле токена

- WHEN у сервера `main` с режимом `token` отсутствует `user` или `token`
- THEN ошибка называет `main`, режим `token`, каждое недостающее поле и соответствующую переменную сервера

### Requirement: Поля секретов соответствуют выбранному режиму

В режимах `basic` и `token` поля учётных данных другого режима из файла или окружения SHALL отклоняться при разрешении настроек, даже если заданы пустой строкой. Ошибка SHALL называть объявленный сервер, выбранный режим и несовместимое поле без значения секрета. Неизвестные ключи секретного файла SHALL отклоняться без раскрытия их текста по требованию безопасности диагностики.

#### Scenario: Поля другого режима

- WHEN в режиме `basic` задано `user` или `token`, либо в режиме `token` задано `proxyUser` или `proxyPass`
- THEN загрузка настроек завершается ошибкой с именем сервера и несовместимым полем

### Requirement: Часовой пояс отчёта задаётся профилем

Поле `report.timeZone` SHALL быть строкой с часовым поясом IANA, по умолчанию `Intl.DateTimeFormat().resolvedOptions().timeZone` машины. Переменная `QA_RUN_TRIAGE_REPORT_TIME_ZONE` SHALL перекрывать файл. Значение SHALL проверяться созданием `Intl.DateTimeFormat` с этим поясом; неверное значение SHALL давать ошибку с полем `report.timeZone`. `config` SHALL показывать значение и источник, `config init` SHALL записывать пояс машины вместе с остальными умолчаниями.

#### Scenario: Пояс не задан

- WHEN `report.timeZone` и переменная отсутствуют
- THEN действует часовой пояс машины с источником `default`

#### Scenario: Пояс из окружения

- WHEN в файле указан `Etc/UTC`, а переменная равна `Asia/Tokyo`
- THEN отчёт и `config` используют `Asia/Tokyo`, источник `env`

#### Scenario: Неверный пояс

- WHEN поле или переменная содержит пустую строку или неизвестный пояс
- THEN команда завершается ошибкой с именем `report.timeZone`

### Requirement: Клоны репозиториев профиля

Файл профиля SHALL содержать список `repos` — абсолютные пути локальных клонов git; список может быть пустым. Происхождение (`origin`) каждого клона SHALL читаться командой git в момент, когда клон нужен команде, а не при чтении файла профиля. Путь из `repos`, который не является каталогом с клоном git, SHALL быть ошибкой, называющей этот путь, в момент обращения к нему.

#### Scenario: Пустой список репозиториев

- WHEN `repos` пуст или не задан
- THEN команды, которым нужен клон, действуют так, будто подходящих клонов нет

#### Scenario: Путь не клон

- WHEN команде нужен клон по пути из `repos`, а по этому пути нет репозитория git
- THEN команда завершается ошибкой, называющей этот путь

### Requirement: Окружение задаётся на уровне профиля

Файл профиля SHALL содержать словарь `environment` — «измерение → список имён параметров билда по убыванию приоритета» с измерениями `env` и `city`, значение по умолчанию `{ "env": ["env"], "city": ["city"] }`. Переопределения на уровне джобы или группы SHALL NOT существовать: свойство `environment` в `jobs.<ключ>` — неизвестное поле, ошибка.

#### Scenario: Окружение общее для всех джоб

- WHEN `environment.env` в профиле равен `["STAND"]`
- THEN у любой джобы окружение `env` берётся из параметра `STAND` её билда

#### Scenario: Попытка переопределить окружение в группе джобы

- WHEN в `jobs.<ключ>` присутствует поле `environment`
- THEN команда завершается ошибкой, называющей это поле и путь файла

### Requirement: Имя профиля не начинается с дефиса

Имя профиля SHALL начинаться с латинской буквы или цифры. Имя, которое начинается с `-`, SHALL быть ошибкой, называющей это имя.

#### Scenario: config use с именем-флагом — ошибка

- WHEN выполнена `config use --json`
- THEN команда завершается ошибкой, называющей `--json`

### Requirement: Клиент CI выбирается по виду сервера

Сетевые команды SHALL обращаться к серверу прогонов через нейтральный клиент. Фабрика `createCiClient` SHALL выбирать реализацию по `servers.<имя>.kind` и MUST быть единственным местом, которое называет вид. Неизвестное значение `kind` SHALL быть ошибкой, называющей поле `servers.<имя>.kind` и поддерживаемые значения. Вид `github` MUST NOT входить в поддерживаемые значения.

#### Scenario: Неизвестный вид сервера в фабрике

- WHEN фабрике передают сервер с `kind`, которого нет среди поддерживаемых
- THEN она завершается ошибкой, называющей поле `servers.<имя>.kind` и поддерживаемые значения
